# SK Defense - 기획 및 개발 로그

이 문서는 `CraftEngine` 기반 스타크래프트 '성큰 디펜스' 스타일 게임(프로젝트명: SK Defense) 개발을 위한 기획 및 로그 문서입니다.

## 📌 기능별 구현 플랜 (Implementation Plan)

### 1. 카메라 시스템 및 줌 (WASD 및 확대/축소)
- **WASD 카메라 이동**: `Level` 또는 `GameManager`에 `CameraOffset` 변수를 추가하여 렌더링 시 오프셋을 적용.
- **맵 확대/축소**: Windows API `SetCurrentConsoleFontEx`를 이용해 콘솔 폰트 크기를 변경하여 줌 인/아웃 효과 구현.

### 2. 마우스 입력 및 터렛 설치 (2x2)
- **터렛 미리보기**: `Input::GetMousePosition()`을 가져와 마우스 커서 위치에 2x2 크기의 터렛 설치 가능 여부를 시각적으로 표시.
- **터렛 설치 및 타일 속성 변경**: 클릭 시 터렛 생성 및 맵 그리드(Grid)의 Walkable 상태 업데이트.

### 3. A* 경로 탐색 알고리즘
- **A* 길찾기 로직 구현**: 타일 맵 기반의 최단 경로 탐색 시스템.
- **동적 경로 재탐색**: 터렛이 설치되어 지형이 바뀔 때마다 맵 내 모든 적(Enemy)들의 경로를 갱신하여 터렛을 피해가도록 함.

### 4. 게임 루프 및 자원/웨이브 시스템
- **웨이브 매니저**: 일정 주기마다 적(Enemy) 생성. 웨이브가 올라갈수록 적의 체력/이동속도 증가.
- **재화(Gold) 시스템**: 적 처치 시 골드 획득. 골드를 소비하여 설치된 터렛을 클릭 시 업그레이드 가능.

### 5. 디버그 모드
- **A* 경로 시각화**: 적이 찾은 노드(경로)를 화면에 다른 색상(예: `*`)으로 그려서 시각적 확인.
- **치트키**: 골드 획득(G), 웨이브 스킵(F1) 기능 구현.

    - 연쇄 합성 지원: 1성 3개가 합쳐져 2성이 되었을 때, 마침 2성이 3개가 되면 즉시 3성으로 연쇄 승급하는 do-while 루프 검사 구조 확립.

- **트러블슈팅 & 고민 해결**:
  - (해결) *엔진 RTTI 함수명 충돌*: 터렛 종류를 반환하기 위해 `GetType()` 함수를 선언했으나, 엔진 매크로 `TYPE_DECLARATIONS`가 내부적으로 생성하는 RTTI 함수 `size_t GetType()`과 이름 및 시그니처가 충돌하는 컴파일 에러 발생. 함수명을 `GetTurretType()`으로 변경하여 충돌 해결.
  - (해결) *신규 생성 액터 리스트 탐색 누락 방지*: 터렛 설치 직후 프레임에서는 새로 생성된 터렛이 `actorList`가 아닌 엔진의 대기 목록(`addRequestedActorList`)에 머무르고 있어 `FindActors`로 즉시 검색되지 않는 구조적 특성 발견. `CheckTurretMerge()` 함수에서 `actorList`와 `addRequestedActorList`를 모두 수집하여 합성 검사를 수행함으로써 설치 즉시 완벽하게 3단 합성이 발동되도록 동기화 완료.

- **트러블슈팅**:
  - **(해결) `ServerCore.pch`를 찾을 수 없음 (C1083) 및 컴파일 오류 지옥**:
    - *원인*: 파일 이동 및 프로젝트 설정 변경 과정에서 `pch.cpp`의 `<PrecompiledHeader>Create` 속성이 누락되어 PCH 파일이 생성되지 않음.
    - *해결*: 파일 수가 적은 라이브러리 환경에서 빌드 시간 차이가 거의 없고 설정 오류만 유발하는 PCH를 `<PrecompiledHeader>NotUsing</PrecompiledHeader>`으로 완전 해제하여 컴파일 안정성 확보.
  - **(해결) `::accept` 호출 시 스택 버퍼 오버플로우 메모리 오염 버그**:
    - *원인*: `::accept(..., reinterpret_cast<SOCKADDR*>(&clientSocket), ...)` 형태로 8바이트 정수 변수 주소에 16바이트 구조체 데이터를 덮어써서 스택과 소켓 변수가 동시에 오염되어 즉시 크래시 발생.
    - *해결*: 주소 전용 구조체 `&clientAddr`로 인자를 정상 전달하여 메모리 오염 원천 차단.
  - **(해결) 비동기 수신 완료 시 세션 객체 자폭(Destroy) 크래시 (0xC0000005)**:
    - *원인*: 수신 완료 시 `recvEvent.owner = nullptr;`을 실행하는 순간, 외부에서 세션을 잡고 있지 않아 레퍼런스 카운트가 0이 되며 `Session` 객체가 스스로 소멸(Delete)됨. 그 상태에서 후속 코드를 실행하여 댕글링 포인터 Access Violation 발생.
    - *해결*: `ProcessRecv` 진입 시 `auto self = shared_from_this();`로 로컬 스코프에서 세션 수명을 안전하게 락업(Lock-up)하여 해결.
  - **(해결) C++ 바이트 역참조(`*reinterpret_cast<T*>`) 이중 포인터 오인**:
    - *원인*: 바이트 포인터(`BYTE*`)를 구조체 포인터로 캐스팅한 후, 함수의 참조형 매개변수(`T&`)로 전달하기 위해 전치 역참조 연산자 `*`를 사용함.
    - *해결*: 포인터 타입 변환과 역참조의 동작 원리를 명확히 분석 및 문서화.
